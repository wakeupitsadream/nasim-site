## 2026-11-04 — Фаза 0 (каркас)

### 1. `proxy.ts` вместо `middleware.ts`
- **Решение:** файл `proxy.ts` в корне, `createMiddleware(routing)` из next-intl. Matcher исключает `api`, `admin`, `_next`, `_vercel` и файлы с точкой.
- **Почему:** в Next 16 `middleware` переименован в `proxy` и всегда работает на Node runtime (`runtime` в нём запрещён).
- **Дальше:** в фазе 5 для `/admin/*` и `/api/admin/*` добавить отдельную ветку прокси с оптимистичной проверкой cookie. Server Actions — это POST на маршрут страницы: если путь исключён из matcher, прокси их не видит, поэтому настоящая проверка прав — в каждом server action и route handler.

### 2. next-intl 4.14 на `next/root-params`
- **Решение:** корневой layout — `app/[locale]/layout.tsx`, файла `app/layout.tsx` нет. `lib/i18n/request.ts` берёт локаль из `next/root-params` по официальному шаблону next-intl. Неизвестная локаль → `notFound()`. `setRequestLocale` и параметр `requestLocale` не используем: они устарели с next-intl 4.13.5–4.13.6.
- **Почему:** это рекомендуемая схема для Next ≥ 16.3. Она совместима с Cache Components, а старая схема — нет (issue next-intl #1493).
- **Следствия:** в Server Actions и Route Handlers root-params недоступен — локаль передаётся явно (`getTranslations({ locale, namespace })`). Админка будет вторым корневым layout со своим `<html>`: переход между сайтом и админкой — полная перезагрузка страницы, это нормально.

### 3. Cache Components включены
- **Решение:** `cacheComponents: true` и `partialPrefetching: true` в `next.config.ts`. Правило 5 CLAUDE.md переписано: `'use cache'` + `cacheLife('max')` + `cacheTag`, инвалидация через `updateTag` в server actions и `revalidateTag(tag, 'max')` в route handlers.
- **Почему:** это дефолт create-next-app 16.4, и Next рекомендует его для всех новых приложений. `partialPrefetching` выставлен явно: ноябрьское security-исправление Next.js касается приложений с Cache Components без него.
- **Ограничения:** экспорты сегмента `revalidate`, `dynamic`, `dynamicParams`, `fetchCache`, `runtime` ломают сборку. `generateStaticParams` должен вернуть хотя бы одно значение. Как читать `params` в `[slug]`-страницах — см. №17.
- **Запасной вариант:** если внутренности next-intl несовместимы с Cache Components — выключить оба флага, вернуть `dynamicParams = false` в `[locale]/layout.tsx` и правило 5 на `unstable_cache`. Не понадобился: сборка и e2e проходят.

### 4. hreflang — только из metadata
- **Решение:** `alternateLinks: false` в routing. Canonical и hreflang (en, ar, ru, x-default = `/en/...`) отдаёт `generateMetadata` через `lib/seo.ts` (`alternatesFor`). Абсолютные URL строятся от `metadataBase` = `NEXT_PUBLIC_SITE_URL`. В фазе 3 добавляется `sitemap.ts`.
- **Почему:** один источник hreflang вместо HTTP-заголовка `Link` и метатегов; Google считает их равнозначными.

### 5. Tailwind через `@tailwindcss/postcss`
- **Решение:** `postcss.config.mjs` с `@tailwindcss/postcss` 4.3.4. Лоадер `@tailwindcss/turbopack`, который ставит create-next-app 16.4.5, убран.
- **Почему:** PostCSS — путь из официальных гайдов Tailwind и shadcn. Turbopack-лоадер вышел 2 ноября 2026, и совместимость shadcn с ним не описана.

### 6. shadcn/ui 4.23: Radix, `radix-nova`, RTL
- **Решение:** `shadcn init --base radix --preset nova --rtl`. В `components.json` `"rtl": true` и стиль `radix-nova`. `DirectionProvider` из `components/ui/direction.tsx` получает направление из локали.
- **Почему:** с июля 2026 shadcn по умолчанию ставит Base UI, а у него открыт баг RTL в dropdown (#9233). Автоконвертация в логические классы работает только для новых стилей, не для `new-york`. Radix-примитивы не читают `<html dir>` — нужен провайдер.
- **Правила на будущее:** портальные компоненты получают `dir={dir}`; `side` у Sheet выбирается по направлению; после каждого `shadcn add` — проверка на `rounded-l/r` (баг #12475) и устаревшие `start-/end-`. CLI `shadcn` лежит в devDependencies: в рантайме нужен только его CSS (`shadcn/tailwind.css`), который импортируется при сборке.

### 7. Токены дизайна и shadcn
- **Решение:** палитра бренда хранится в `styles/design-tokens.css` в неймспейсе `--nasim-*`. Семантические переменные shadcn (`--background`, `--primary`, `--accent`, …) ссылаются на них в `app/globals.css`. Свои утилиты: `bg-surface-2`, `bg-whatsapp`, `bg-telegram`, `text-highlight`, `text-h1`/`h2`/`h3`/`body`/`lead`/`small`, `shadow-card`, `max-w-page`, `px-gutter`.
- **Почему:** исходный файл токенов использовал имена `--color-*`, которые конфликтовали с переменными темы Tailwind и shadcn (`--color-primary`, `--radius-sm` и др.). Отдельный неймспейс убирает конфликт, а значения правятся в одном месте.
- **Конфликт «accent»:** у shadcn `accent` — фон наведения в меню, поэтому это мягкая бирюза `#d9f2ef`. Яркая бирюза бренда `#19b3a6` доступна как `highlight`.
- **Тёмная тема:** блок `.dark` удалён. `@custom-variant dark` оставлен страховкой: класс `.dark` никогда не ставится, поэтому `dark:`-классы из компонентов shadcn не срабатывают. Начиная с фазы 1 их вычищают из каждого добавленного компонента (правило 13).
- **Арабская типографика:** `[dir="rtl"]` увеличивает `--nasim-font-scale` до 1.06, и размеры `text-*` масштабируются автоматически.

### 8. Шрифты
- **Решение:** IBM Plex Sans (latin + cyrillic, вариативный) и IBM Plex Sans Arabic (400–700, subset arabic, `preload: false`) объявлены в корневом layout. `html[lang="ar"]` переключает `--nasim-font` на арабский.
- **Почему:** корневой layout не может выбирать шрифты по локали, не становясь динамическим. `preload: false` не даёт /en и /ru скачивать арабские файлы; e2e проверяет, что арабский шрифт загружается только на /ar.

### 9. Drizzle 0.45 + `pg` Pool
- **Решение:** drizzle-orm 0.45.4 и drizzle-kit 0.31.11 (стабильная ветка). Рантайм — `pg` Pool (`max: 5`) поверх pooled-строки Neon (`DATABASE_URL`, PgBouncer) с `attachDatabasePool` от `@vercel/functions`. Миграции — по `DATABASE_URL_UNPOOLED`, в `pnpm build` через `scripts/migrate-if-db.mjs` (по образцу daylik). Без URL сборка идёт дальше с предупреждением.
- **Почему:** Drizzle 1.0 пока только RC, хотя документация Drizzle уже написана под него. Отсюда правило 15: сниппеты из документации не копировать без проверки. Neon для Vercel Fluid рекомендует TCP-пул с `attachDatabasePool`. Выбор pooled-строки для рантайма документацией не зафиксирован; маленький клиентский пул поверх PgBouncer — консервативный вариант, пересмотреть при нагрузке.
- **Обязательно при подключении:** preview-ветки Neon включить до первого PR-деплоя, иначе превью-сборка мигрирует продакшен.
- **Схема фазы 0:** таблица `settings` — синглтон (`id = 1`, CHECK) с `brand_name` (I18nText) и `updated_at`. Миграция `0000_init_settings`. CI проверяет, что схема и миграции синхронны и что миграции идемпотентны.

### 11. pnpm 10, Node 22.12–24

Node 26 — дефолт Vercel для новых проектов, но в нём встроенный `fetch` перешёл на HTTP/2; без проверки не берём. TypeScript остаётся на 5.9 (create-next-app ставит `^5`, хотя `latest` в npm — 7.0).
- **Postinstall-скрипты:** `@parcel/watcher`, `@swc/core`, `esbuild`, `sharp`, `unrs-resolver` перечислены в `ignoredBuiltDependencies`. Бинарники приходят через optionalDependencies, сборка и drizzle-kit работают без них.

### 12. `formatAED` и направление текста

### 17. Настоящий 404 для неизвестных slug: `ensureStatic = 'navigation'`
- **Проблема:** с `partialPrefetching` для slug вне `generateStaticParams` Next сначала отдаёт App Shell со статусом 200. `notFound()` срабатывает уже после начала стрима — получается «мягкий 404» (200 + `noindex`).
- **Решение:** страницы `services/[slug]` и `areas/[slug]` экспортируют `ensureStatic = 'navigation'` и проверяют slug до любого `<Suspense>`. Для незаявленного значения первый запрос ждёт полный рендер, поэтому `notFound()` даёт статус 404. Заодно Next проверяет при сборке, что маршрут целиком статический.
- **Проверено:** `/en/areas/mirdif` (неопубликованный район) и `/ar/services/no-such-service` → 404; в браузере — локализованная страница «не найдено» с правильными `lang`/`dir`. Закреплено в e2e.
- **Следствие для фазы 2–3:** данные этих страниц должны идти только через `'use cache'` с долгим `cacheLife` — некешируемые запросы к БД и runtime-данные `ensureStatic` не пропустит.

### 18. CI-workflow лежит в `docs/ci/ci.yml`
- **Проблема:** у GitHub-токена облачной сессии нет права `workflows`, поэтому GitHub отклоняет любой пуш с `.github/workflows/*` (ответ «Internal Server Error»; без этого файла та же ветка пушится).
- **Решение:** workflow хранится в `docs/ci/ci.yml`. Максим один раз переносит его в `.github/workflows/ci.yml` через веб-интерфейс GitHub (README → «CI»). До этого «CI зелёный» из DoD фазы 0 проверен локально тем же набором команд, но не в GitHub Actions.
- **Альтернатива:** выдать GitHub App право `workflows` — тогда облачные сессии смогут сами менять workflow.

### 20. Превью открытые, продакшен вне поиска до своего домена
- **Превью без Vercel Authentication** (`ssoProtection: null`): на Hobby Мишу нельзя добавить в команду, а ссылка-исключение одна на аккаунт. Vercel сам ставит превью `X-Robots-Tag: noindex`.

- **`siteUrl()`** (`lib/env.ts`): `NEXT_PUBLIC_SITE_URL` → на продакшене `VERCEL_PROJECT_PRODUCTION_URL` → на превью `VERCEL_BRANCH_URL`, затем `VERCEL_URL` → `localhost`. Так canonical/hreflang корректны без ручной переменной. `lib/seo.ts` реэкспортирует её.

### 23. `cn` с учётом наших токенов
- **Проблема (проверено запуском):** `cn` из пакета `cn` (его ставит shadcn 4.23) не знает `text-small/body/lead/h1…`, `shadow-card`, `h-tap` и т. п. и при слиянии с цветом выкидывает размер шрифта (`cn('text-body', 'text-primary')` → `text-primary`).
- **Решение:** `lib/utils.ts` строит `cn` через `createCn` из `cn/config` с `extend` (spacing `tap/gutter/gutter-lg/sticky-bar/header`, font-size `small/body/lead/logo/h1/h2/h3`, shadow `card/float`). Все компоненты импортируют `cn` только из `@/lib/utils`; импорт `from "cn"` в `app/` и `components/` ловит `pnpm lint`. Новый токен шрифта/отступа — добавить и в `lib/utils.ts`.

### 24. Адаптация компонентов shadcn
- **Sheet:** логические стороны `inline-start`/`inline-end` (по умолчанию `inline-end`: справа в EN, слева в AR), `left`/`right` принимаются как алиасы и маппятся по направлению (понадобится `sidebar` в фазе 5). `dir` — из `useDirection()`. Обязательный проп `closeLabel` (строка из messages). Ширина задаётся вариантом `data-[side=inline-end]:w-…`, обычный `w-…` его не перебивает.
- **Select:** `dir` в портал Radix берёт из `DirectionProvider` сам — явная передача безвредна, но не нужна. Индикатор — `inset-e-2`.
- **Table:** серверный компонент; контейнер — `role="region"` с `tabIndex={0}` и именем (`labelledBy` на caption или `label`), иначе axe `scrollable-region-focusable`; проп `stickyFirstColumn` для таблиц цен на мобильном.
- **Breadcrumb:** обязательный `label` (имя landmark из messages), `BreadcrumbEllipsis` удалён. JSON-LD BreadcrumbList — в фазе 3 вместе с SEO-слоем.
- **Sonner:** без `next-themes` (тёмной темы нет, зависимость удалена), `theme="light"`, `top-center`, `dir`. `<Toaster />` монтируется только на страницах с уведомлениями (сейчас — dev/ui, в фазе 4 — формы), не в корневом layout.
- **Размеры:** интерактивные элементы ≥ 44px (`h-tap`), текст полей `text-body` (17px — iOS не зумит). `sm`/`xs` у кнопок — только для плотной админки.

### 46. `POST /api/diagnose`: zod на границе, честные статусы, временный rate limit
- **Решение:** `lib/validation/diagnose.ts` — одна схема запроса для клиента и сервера (текст ≤ 600 символов или фото JPEG/PNG/WebP ≤ 3 МБ в base64) и схема ответа. Ошибки маппятся на коды, которые UI объясняет без вранья: 503 `unavailable` (нет ключа или лимит провайдера), 422 `refused`, 429 `rate_limited`, 502 `failed`, 400 `invalid`. В логи попадает только имя класса ошибки (правило 7), текст и фото клиента нигде не сохраняются (правило 11: без подтверждения в БД ничего не пишется — здесь не пишется вообще).
- **Rate limit — ВРЕМЕННО:** `lib/ratelimit.ts` — in-memory скользящее окно: 6 запросов в минуту на `sha256(ip + IP_HASH_SALT)` и 60 в минуту на инстанс. На serverless-инстансах счётчики не общие, это защита от случайного спама, а не от атаки. Фаза 4 заменяет его таблицей `rate_limits` (та же сигнатура `allow(key, rule)`) и Turnstile на форму диагностики, если появится злоупотребление.
- Линт-guard расширен: клиентские компоненты не импортируют `@/lib/ai`, `@/lib/ratelimit` (и по-прежнему `@/content/seed`, `@/lib/content`, `@/lib/sanitize`).

### 47. UI диагностики: клиентский островок, фото сжимается в браузере, результат ревьюится без ключа
- **Размещение:** секция `#diagnose` на главной сразу после hero (`#book` переведён на песочный тон, чтобы соседи не совпадали) и на `/services` вместо полосы «Не уверены?» (её текст заменила сама диагностика; ссылка «Открыть калькулятор» осталась внутри секции). В hero — тихая ссылка «Не знаете, что сломалось? → AI-диагностика».
- **Форма** (`components/diagnose/diagnose-form.tsx`): textarea + четыре примера-чипа (заполняют поле — главный способ «попробовать за секунду») + «Добавить фото». Фото уменьшается до 1280 px и перекодируется в JPEG 0,82 через canvas до отправки (`components/diagnose/image.ts`): меньше трафика, EXIF с геолокацией не уходит, лимит роута не достигается. `capture` на input не ставим: на Android он убирает выбор из галереи. ## 2026-11-05 — «Живой» сайт: движение, переходы, детали

### 48. Движение — CSS-first система `styles/motion.css`, без JS-библиотек анимации
- **Решение:** всё движение сайта — CSS: появление блоков при прокрутке через scroll-driven animations (`animation-timeline: view()`, Baseline с Firefox 159, октябрь 2026), входная анимация hero по времени со stagger через `--i` (`stagger(i)` в `lib/motion.ts`), шапка получает линию и тень через `scroll()`-timeline, волны бриза в фирменной графике и кольца эмблемы «дышат», иконки услуг оживают при наведении (карта `ICON_MOTION` → `data-motion`), галочки доверия рисуются (`stroke-dashoffset`), число «после» в сравнении температур считается вниз (`CountUp`: client, IntersectionObserver, формат каждого кадра через `formatNumber`), FAQ на `<details>` раскрывается плавно через `::details-content` + `interpolate-size` (пока только Chromium, остальные — мгновенно). Только compositor-свойства (opacity/translate/scale/rotate); `tests/unit/motion.test.ts` проверяет, что каждое правило под `prefers-reduced-motion: no-preference`, scroll-driven — под `@supports`, а keyframes не трогают layout-свойства.
- **Почему не библиотека:** motion/framer, GSAP ScrollTrigger, Lenis дают то же самое за 30–60 KB JS и собственный скролл; платформа уже умеет всё нужное, а серверные маркетинговые страницы остаются без клиентского JS. Без поддержки (старые браузеры) страница просто статична — ничего не скрыто до JS.
- **Правила, добытые тестами:** интерактивные контейнеры (форма диагностики, карточки мастера, чипы районов, меню услуг, FAQ, футер, заголовки с кнопками) получают только `.reveal-fade` — сдвиг на 18px во время прокрутки уводил тап мимо цели (поймано e2e под нагрузкой: клик приходил в зазор формы); предки `.reveal` обрезают через `overflow-clip`, не `overflow-hidden` (hidden делает блок scroll-контейнером, и view-timeline замирает); `html { scroll-behavior: smooth }` только для якорей, а `data-scroll-behavior="smooth"` на `<html>` велит Next 16 сбрасывать его на SPA-навигации.

### 49. Переходы страниц и шагов — React `<ViewTransition>` (React 19.3, Next 16.4 без конфигурации)
- `components/page-transition.tsx` оборачивает контент каждого `page.tsx` (не layout: он не перемонтируется): короткий fade по умолчанию, направленный сдвиг по `transitionTypes` у ссылок — карточки и меню услуг «вперёд», хлебные крошки «назад»; в RTL направление зеркалится правилами `:root[dir='rtl']::view-transition-*`. Шапка и мобильная панель закреплены (`viewTransitionName`), так что движется контент, а опора стоит. Шаги мастера заявки и смена «форма → вердикт» в диагностике — тот же механизм (`<ViewTransition key>` + `startTransition`), классы `.step-in/.step-out`. `::view-transition { pointer-events: none }`, при reduced motion длительности 0. Same-document View Transitions — Baseline с Firefox 144.
- **Тесты:** Playwright запускает Chromium с `--disable-smooth-scrolling` (автоматика кликала до конца плавной прокрутки); форма диагностики помечает гидратацию атрибутом `data-ready` (`useSyncExternalStore`, без setState в эффекте) и тесты ждут его, а не гонятся с бандлом. `tests/e2e/motion.spec.ts` проверяет reduced motion (ничего не анимируется и не скрыто), появление по скроллу, линию шапки, переход каталог → услуга → назад, иконки при наведении, прогресс мастера и зеркальный origin в RTL.

## 2026-11-05 — AI через шлюз Polza AI

### 51. Шлюз Polza AI вместо прямого ключа Anthropic
- **Решение:** `lib/ai.ts` ходит в OpenAI-совместимый шлюз Polza AI (`https://polza.ai/api/v1/chat/completions`, заголовок `Authorization: Bearer pza_…`) обычным `fetch` через `lib/ai/gateway.ts`, без SDK; `@anthropic-ai/sdk` удалён (№45 в части провайдера заменено). Ключ — аккаунт Максима, оплата рублями (карта РФ, СБП, пополнение от 100 ₽), работает без VPN; аккаунт Anthropic у Миши и его ключ больше не нужны. Модель по умолчанию `anthropic/claude-opus-5.5` (идентификаторы Polza — с префиксом вендора и точкой в версии), переключение через `AI_MODEL`; `AI_BASE_URL` + `AI_API_KEY` подставляют любой другой OpenAI-совместимый шлюз; `AI_EFFORT` — усилие рассуждения (`low` по умолчанию: триаж короткий, визитёр ждёт; пустое значение оставляет умолчание провайдера).
- **Почему OpenAI-протокол, а не Anthropic-совместимый `https://polza.ai/api`:** у Polza он основной и задокументированный, с таблицей возможностей по моделям (картинка на входе, строгий JSON через `response_format`, reasoning, стриминг); Anthropic-совместимый режим описан только для Claude Code и Claude Desktop, и неизвестно, пропускает ли шлюз `output_config`, `fallbacks`, `cache_control` и beta-заголовки. Структурированный ответ держится на трёх опорах: `response_format: json_schema` со схемой из zod (`z.toJSONSchema` в zod 4 сразу даёт строгий диалект — `additionalProperties: false`, все поля обязательны, nullable как `["string","null"]`), та же форма ответа словами в системном промпте (`ANSWER_SHAPE`, тест сверяет с ключами схемы) и обязательный `safeParse` zod у нас — если шлюз проигнорирует схему, ответ не пройдёт, а не отобразится криво. JSON извлекается из текста и при обёртке в markdown-fences.
- **Ошибки:** 401/403 (ключ), 402 (кончился баланс Polza), 429 (лимит) → визитёру «пока недоступно» (503) и строка в лог со статусом и кодом; 5xx, таймаут 45 с, нечитаемый или не по схеме ответ → «не получилось» (502); отказ модели (`finish_reason: content_filter` или `refusal`) → 422. Контент клиента и текст ответа в логи не попадают.
- **Стоимость (цены Polza на 05.11.2026, обновляются ежечасно):** Opus 5.5 — 379 ₽ / 1 897 ₽ за MTok (вход/выход), Sonnet 5.5 — 190 / 949 ₽, Haiku 5.5 — 11,86 / 59,28 ₽. Диагноз ≈ 1,5 тыс. токенов системного промпта + ~1,6 тыс. за фото + ~400 на ответ и рассуждение → ≈ 1,5–2 ₽ на Opus, ≈ 0,8 ₽ на Sonnet, ≈ 0,05 ₽ на Haiku; тысяча диагнозов в месяц — до 2 000 ₽. Это примерно на 15–20 % дороже прямых цен Anthropic в пересчёте по курсу — плата за рубли и отсутствие зарубежного аккаунта. Кэширование промпта через шлюз не задокументировано — не используем (экономия была бы ≈ 0,5 ₽ на запрос).
- **Отклонено:** Anthropic SDK с `baseURL` Polza (неизвестный пропуск параметров, авторизация только Bearer), пакет `openai` (одна ручка — зависимость не нужна), прямой ключ Anthropic через Мишу (оплата и аккаунт на другой стороне, регион).
- **Проверка 05.11.2026 (превью Vercel, `anthropic/claude-opus-5.5`, `AI_EFFORT=low`):** три живых запроса прошли по схеме с первого раза — RU-текст (запах + капли → глубокая чистка, 4 причины, 3 вопроса) 9,3 с; EN с фото загрязнённого блока (модель описала тёмные точки на жалюзи → глубокая чистка) 7,3 с; AR-текст (слабое охлаждение → чистка, ответ по-арабски) 9,7 с; полный путь в браузере (форма → карточка → ссылка на запись) 7,9 с. `response_format` шлюз принял, `reasoning.effort` не отверг, строгий JSON пришёл без обёрток. Если 7–10 с покажутся долгими — `AI_MODEL=anthropic/claude-sonnet-5.5` вдвое дешевле и заметно быстрее при том же формате. Ключ в Vercel был заведён только для Production: переменные применяются к новым деплоям, поэтому цель Preview добавлена и превью пересобрано — любое изменение env требует нового деплоя.

Финальная тёмная полоса получила подложку — ночной Дубай (фото, приглушено `opacity` и затенено со стороны текста классом `.band-shade`, в RTL зеркально), перекличка с фоном нового лого; остальные тёмные полосы остались графитовыми, красный по-прежнему только акцент.
- **Фото:** Миша попросил живые фотографии (скриншот карточек мастера с line-art: «добавь картинок»); своих пока нет, поэтому временно стоят стоковые с Pexels — Pexels License разрешает коммерческое использование без обязательной атрибуции, но автор и ссылка на страницу фото записаны в `credit` каждой записи. Слой: `content/seed/media.json` → `mediaRecordSchema` (`kind`: hero / band / category / service / team / before_after, `service_slug`, `category`, `url` под `public/photos/`, `width`/`height`, `alt` на трёх языках, `credit`, `sort`) → `getMedia(filter)` и `getPhoto(filter, locale)` в `lib/content/queries.ts` с сигнатурами будущих запросов к БД: фаза 2 заменит тела на таблицу media (Blob-URL вместо пути), страницы не меняются. Где стоят: hero главной (`hero` — гостиная с настенным кондиционером и диваном, обе услуги в одном кадре, LCP с `priority`), карточки категорий мастера (`category`, через payload: клиентский островок слой контента не импортирует), слот каждой из десяти активных услуг (`service`), подложка финальной полосы (`band`); `MediaFrame` принимает уже выбранное фото (`Photo` с alt под локаль) и без него рисует прежний плейсхолдер. Отбор: около девяноста кандидатов по описаниям со страниц поиска Pexels, просмотрены контакт-листами, выбраны кадры без чужих логотипов, без «больничной» и без «ремонтно-гаражной» эстетики; файлы пережаты sharp (JPEG q80, ширина 1200 / 1600 / 1920, 2,6 МБ на 16 файлов в `public/photos`, дальше `next/image` отдаёт AVIF/WebP под размер). Unsplash не использован: прямая загрузка требует ключ API.
- **Честность:** стоковые кадры не выдаются за работу бригады — alt описывает только сюжет, подписей «наши работы» нет, блок «до/после» по-прежнему без фото (`before_after` пуст). Как только Миша пришлёт свои снимки, замена — записи в media.json, в фазе 2 — через админку. `tests/unit/content.test.ts` следит, что у каждой активной услуги есть фото, файлы существуют, ссылки на услуги верны, alt выбирается по локали.
- **Отклонено:** AI-сцена в hero (красные футболки противоречат новому лого, и фото на главном экране честнее иллюстрации); Unsplash (ключ API); оставить line-art вместо фото в карточках мастера (Миша попросил именно картинки); фото из референса с фургоном (логотип стороннего автопроизводителя, №52).

### 54. Годовые контракты и «О нас», клик по словесному знаку, шторка без наложений
- **Страницы.** `/annual-contracts` (BRIEF §6.4): три тарифа из `prices.json` карточками (состав из `includes`, «Рекомендуем» у `highlighted`, наклон за курсором), таблица «из чего складывается экономия» — визиты тарифа посчитаны движком цен (`annualPlanComparison` в `lib/pricing.ts`, unit-тесты: Essential 1 521 → 899, Comfort 3 235 → 1 499, Villa 3 576 → 2 499 при сплит-ценах; фанкойлы дороже, оговорка в тексте), «что входит в визит» из `includes` услуги ac-cleaning, три шага на тёмной полосе, FAQ scope `contracts`, CTA — WhatsApp по `wa.template.contract` с названием тарифа (пока контактов нет — `/contact`, №22); форма «запросить контракт» (лид типа `contract`) — фаза 4 вместе с формой заявки. `/about` (§6.6): лид и строки доверия рядом с ночным портретом экипажа, история из блока `about.body` (заглушка переписана в честный текст о том, как мы работаем — без выдуманных цифр, стажа, лицензий и состава команды; факты Миша даст по анкете 7в), стандарты техника (пять пунктов, UI-строки), «чего мы не делаем» из `about.not_doing`, реквизиты только когда заполнены, районы, финальная полоса. Команда и партнёры — когда появятся фото и факты (`media.kind = team`). `/pricing` не менялся: он заполнен с фазы 3a, а «пустым» показался из-за автопрокрутки к мастеру в dev-режиме (исправлено в №52). Экономика контрактов — вопрос Мише (анкета 27г): при ценах прайса Comfort даёт 54 % скидки.
- **Логотип.** Растянутая ссылка `::after` не ловила клики по словесному знаку: у знака `-skew-x-6`, а трансформированный элемент рисуется поверх псевдоэлемента ссылки, стоящей раньше в DOM. Исправление — `pointer-events-none` на словесном знаке и подписи; e2e кликает по буквам в шапке и в футере на трёх локалях и ждёт главную.
- **Переходы страниц.** Под шторкой старая страница ещё уезжала, новая поднималась (`nasim-rise` / `nasim-slide-x`), а группа `.page-fade` интерполировала высоту между страницами разной длины — три движения сразу читались как наложение и подтормаживали. Теперь хореография одна: шторка (0,56 с) закрывает экран к 42 %, под ней старая страница и корень гаснут (236–296 мс), новая страница просто стоит на месте с 300 мс, после 54 % шторка уходит; у групп страниц `animation: none` (геометрию не тянем). Направление — подсказка «вперёд / назад»: у `nav-back` шторка едет с другой стороны (`animation-direction: reverse`), в RTL зеркально через `--nasim-curtain-dir`. Переходы без типа (кнопки браузера) — короткий fade без шторки. Слайды `nasim-slide-x` и их RTL-правила удалены; unit-тест motion проверяет зеркало шторки и `animation: none` у групп страниц.
